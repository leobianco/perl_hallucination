# Experimental: Terminal Token Mismatch in RM Training vs. PE-RL Rollout Scoring

This directory implements an isolated, modular experiment to investigate the effect of terminal token mismatches between Reward Model (RM) training and Parameter-Efficient Reinforcement Learning (PE-RL) rollout scoring.

---

## 1. Background & Hypothesis

In standard sequence classification reward modeling on decoder-only models (like Gemma), the classification head pools the hidden state at the final non-padded token position:
$$r(x, y) = \text{ScoreHead}(h_T)$$

### The Phenomenon:
- **RM Training**: Reward models are typically trained on text formatted with `<eos>` (or raw text), pooling at the final `<eos>` token position.
- **PE-RL Rollouts**: Conversational policy models generate completions stopping at `<end_of_turn>`. When feeding rollout completions to the reward model, the RM scores the hidden state at `<end_of_turn>` rather than `<eos>`.

### Scientific Explanations & Intuition:
1. **Implicit Regularization / Anti-Overfitting**:
   Evaluating on a slightly shifted terminal token (`<end_of_turn>` vs `<eos>`) creates an out-of-distribution smoothing effect. This prevents the policy from reward-hacking brittle, over-optimized token transitions at the exact training termination token.
2. **Attention Sink & Global Semantic Pooling**:
   Both `<eos>` and `<end_of_turn>` act as attention sinks in causal transformers. By step $T$, self-attention has already integrated bidirectional-like contextual information across the entire prompt + completion.
3. **Dialogue Contextualization**:
   In instruction-tuned models, `<end_of_turn>` explicitly captures conversational closure semantics without requiring an artificial document-ending `<eos>` token.

## 2. Experimental 2x2 Matrix

| Experiment | RM Training Token | PE-RL Scoring Token | Description |
| :--- | :--- | :--- | :--- |
| **A (Matched EOS)** | `<eos>` | `<eos>` | Standard document closure consistency |
| **B (Matched EOT)** | `<end_of_turn>` | `<end_of_turn>` | Standard dialogue turn consistency |
| **C (Mismatched EOS/EOT)** | `<eos>` | `<end_of_turn>` | **Observed configuration (Empirically validated)** |
| **D (Mismatched EOT/EOS)** | `<end_of_turn>` | `<eos>` | Inverse mismatch control |
| **E (Untagged)** | `none` | `none` | Raw text baseline without terminal special tokens |

## 3. Usage

### Training the Reward Model
```bash
# 1. Train RM with <eos> (default)
./scripts/token_mismatch/reward_model.sh npov

# 2. Train RM with <end_of_turn>
RM_TERMINAL_TOKEN="end_of_turn" ./scripts/token_mismatch/reward_model.sh npov

# 3. Train RM with no terminal token
RM_TERMINAL_TOKEN="none" ./scripts/token_mismatch/reward_model.sh npov
```

### Running PE-RL (RLOO)
```bash
# 1. Score rollouts on <end_of_turn> (the observed mismatch setup if RM was trained on <eos>)
SCORING_TERMINAL_TOKEN="end_of_turn" ./scripts/token_mismatch/perl.sh npov

# 2. Score rollouts on <eos> (matched setup with RM trained on <eos>)
SCORING_TERMINAL_TOKEN="eos" FORCE_TERMINAL_TOKEN_SWAP="true" ./scripts/token_mismatch/perl.sh npov

# 3. Score exactly as generated by policy
SCORING_TERMINAL_TOKEN="as_generated" ./scripts/token_mismatch/perl.sh npov
```

### Running W&B Sweeps
```bash
# RM Token sweep
wandb sweep scripts/token_mismatch/sweep_rm_mismatch.yaml

# PE-RL Scoring Token sweep
wandb sweep scripts/token_mismatch/sweep_perl_mismatch.yaml
```
